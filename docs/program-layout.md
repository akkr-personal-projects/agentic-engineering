# Program Layout and State Files

> Read by every step of the Agentic Engineering prompt list (generated by `tools/agentic-prompts`). This document holds only the repository layout, the naming rules and the state-file templates. It contains no facts about the CLIs: each step takes those from the research it does at that time.
>
> Japanese version: [program-layout.ja.md](./program-layout.ja.md)

## 1. Documentation tree

```text
docs/
├── program-layout.md (+ .ja.md)                  # this document
├── INDEX.md                                      # state: one line per document (§4)
├── PROGRESS.md                                   # state: one row per step (§4)
├── DIGEST.md                                     # state: append-only summaries (§4)
├── {slug}-for-cli-agents.{cli}.md (+ .ja.md)     # research of a cross-cutting method, one per CLI
└── {NN}-{slug}/                                  # one directory per other method
    ├── research.{cli}.md (+ .ja.md)              # step NN-1
    ├── plan.{cli}.md (+ .ja.md)                  # step NN-2
    └── implementation.{cli}.md (+ .ja.md)        # step NN-3
```

Naming:

| Placeholder | Meaning | Example |
| --- | --- | --- |
| `{NN}` | The method's number in the prompt list, two digits | `05` |
| `{slug}` | The method's name in lower case, non-alphanumerics replaced by `-` | `spec-plan-engineering` |
| `{cli}` | `claude-code`, `codex` or `antigravity` | `claude-code` |

Rules for documents:

- The English `.md` is the source. The `.ja.md` is a faithful translation with the same `##` and `###` headings.
- Agents read only the English `.md` files.
- Research documents start with their research date. Anything not verified against official documentation is marked "unverified".
- Every implementation document ends with a "Summary for later steps" section of at most 15 lines: what exists, where, how to invoke it, what to avoid.

## 2. Implementation tree

The first implementation plan defines this skeleton. Later plans keep it and propose any change under "Migration".

```text
repo/
├── AGENTS.md            # always-on, at most 15 lines (template in §5)
├── CLAUDE.md            # contains "@AGENTS.md"
├── docs/                # §1
├── shared/              # canonical, CLI-neutral artifacts
│   ├── skills/          # Agent Skills (SKILL.md with standard frontmatter, plus references/, scripts/, assets/)
│   ├── templates/       # document templates (specs, plans, progress notes, ...)
│   ├── scripts/         # deterministic checks and helpers
│   ├── hooks/           # hook scripts shared by the CLIs
│   └── evals/           # evaluation cases and graders
├── claude-code/         # install root for Claude Code CLI
├── codex/               # install root for Codex CLI
└── antigravity/         # install root for Antigravity CLI
```

Rules for the implementation:

- `shared/` holds one canonical copy of each artifact. A CLI root holds only what that CLI needs to find and use the shared artifacts (configuration, rules, links or synced copies, adapters).
- A CLI root is created by the first plan for that CLI. Where files go inside it, and how the CLI discovers them, comes from that CLI's research, verified against current official documentation.
- If a method is already implemented for another CLI, reuse `shared/` and add adapters. Do not fork shared artifacts per CLI.
- Each CLI root can be tested by starting that CLI inside it.

## 3. Working rules

- One step per prompt, each in a fresh session, in the order of the prompt list. Review the result before the next step.
- Research steps (`-1`) research. Plan (`-2`) and implementation (`-3`) steps read what exists and research only to verify a fact they depend on.
- After each step, update the state files (§4) and commit. Commit messages are prefixed `{NN}-{slug}({cli}):`.
- Program state lives in the state files and git, not in an agent's personal memory.

## 4. State files

Create these files with the content below if they do not exist. Each step updates them.

`docs/INDEX.md`:

```markdown
# Index

One line per document. English files only; each has a .ja.md translation.

| Step | CLI | Document | Path | One line |
| --- | --- | --- | --- | --- |
```

`docs/PROGRESS.md`:

```markdown
# Progress

One row per step, in the order of the prompt list.

| Step | CLI | Status | Date | Session | Files | Open questions / approvals |
| --- | --- | --- | --- | --- | --- | --- |
```

`docs/DIGEST.md`:

```markdown
# Digest

Append-only. At most 8 lines per research or plan step, at most 15 lines per implementation step. Newest at the bottom.
Write facts a later step needs (paths, commands, decisions, constraints), not narrative.
```

Example entries:

```markdown
| 05-1 | claude-code | Spec / Plan Engineering research | docs/05-spec-plan-engineering/research.claude-code.md | Plan modes, spec and plan formats, implications |
| 05-1 | claude-code | done | 2026-10-05 | ae-05-1-claude-code | docs/05-spec-plan-engineering/research.claude-code.md | — |

## 05-1 claude-code
- ...
```

## 5. Repository-root AGENTS.md template

```markdown
# agentic-engineering
Reference implementation of Agentic Engineering methods for Claude Code CLI, Codex CLI and Antigravity CLI.
- Layout and state: docs/program-layout.md; docs/INDEX.md, docs/PROGRESS.md, docs/DIGEST.md
- shared/ is canonical; claude-code/, codex/, antigravity/ are install roots. Fix shared problems in shared/, not in a CLI root.
- Docs: English .md is the source; .ja.md mirrors its headings. Read only .md files.
- Prompts for each step: tools/agentic-prompts (generated list in prompts/).
```

`CLAUDE.md` at the repository root contains only `@AGENTS.md`.
